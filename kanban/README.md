# Syntonia Kanban

Лёгкая локальная канбан-доска для совместной работы человека и агента над
вёрсткой Syntonia. Без npm-зависимостей: только Node.js (`node:http`,
`node:fs`, `node:path`), ванильные HTML/CSS/JS и `board.json` как хранилище.

## Запуск

```bash
cd /Users/gleb/Documents/deepseek-harness/default-workspace/syntonia-v2/kanban
node server.mjs
```

Открыть: <http://127.0.0.1:4324>

Сервер слушает только `127.0.0.1:4324`. Остановка — `Ctrl+C`.
`npm install` не нужен; достаточно Node.js 18+.

## Что умеет

- Четыре колонки: бэклог, в работе, ревью, готово.
- Drag-and-drop карточек между колонками и сортировка внутри колонки
  (нативный HTML5 DnD).
- Добавление, редактирование и удаление карточек. Редактирование — по клику
  на карточку или по Enter/Space с клавиатуры.
- В редакторе можно сменить колонку — это запасной способ перемещения для
  тач-устройств, где HTML5 DnD не работает.
- Каждое изменение сразу сохраняется в `board.json`; индикатор в шапке
  показывает «Сохранено», «Сохраняем…» или «Ошибка сохранения» с кнопкой
  «Повторить».
- Фильтр по ответственному: все / агент / человек. «Вместе» показывается в
  обоих фильтрах. Счётчики колонок учитывают текущий фильтр.
- Кнопка «Обновить» перечитывает доску с сервера. Если есть несохранённые
  изменения, она сначала предложит подтверждение.
- Адаптивная вёрстка: на узких экранах колонки листаются горизонтально.
- Перед закрытием вкладки с несохранёнными изменениями браузер попросит
  подтверждение.

## API

### `GET /api/board`

Возвращает `board.json` (нормализованный JSON):

```json
{
  "columns": [
    {
      "id": "backlog",
      "title": "Бэклог",
      "cards": [
        {
          "id": "backlog-process",
          "title": "Process",
          "description": "Секция процесса: четыре шага и мобильная раскладка.",
          "tag": "Section",
          "assignee": "agent",
          "priority": "high",
          "createdAt": "2026-11-04T07:00:00.000Z"
        }
      ]
    }
  ]
}
```

Правила данных:

- `columns` — ровно четыре колонки с `id`: `backlog`, `progress`, `review`,
  `done`; у каждой русское название и массив `cards`.
- `assignee`: `agent` | `human` | `both`.
- `priority`: `high` | `medium` | `low`.
- `createdAt` — корректная ISO-дата.
- `id` карточек уникальны в пределах доски.
- Необязательные `description` и `tag` могут быть пустыми строками.

### `PUT /api/board`

Принимает ту же структуру целиком. Тело ограничено 2 МБ. Сервер проверяет
типы, обязательные поля, перечисления и уникальность id. При ошибке —
`400` и `{ "error": "...", "details": ["..."] }`, файл не меняется.

Успешная запись атомарная: JSON пишется во временный `.board-*.tmp` в папке
`kanban/`, затем `rename` подменяет `board.json`. Ответ:

```json
{ "ok": true, "savedAt": "2026-11-04T17:40:00.000Z", "cards": 18 }
```

Всё остальное отдаётся как статика из `public/`. Неизвестные `/api/*`
возвращают JSON 404.

## Ограничения

- Это локальный инструмент без авторизации; не выставляйте порт в сеть.
- Нет real-time синхронизации между вкладками/людьми: последняя запись
  побеждает, для чужих изменений используйте «Обновить».
- HTML5 drag-and-drop не работает на тач-экранах; там перемещение доступно
  через выбор колонки в редакторе карточки.
- Нет истории версий и корзины: удаление подтверждается, но не отменяется.
  `board.json` можно версионировать средствами git.
- При фильтре перетаскивание учитывает только видимые карточки; скрытые
  сохраняют свой порядок.
- Если `board.json` вручную отредактирован с ошибкой, `GET /api/board`
  вернёт 500 с описанием проблемы, а интерфейс — «Ошибка загрузки».
- Порт 4324 зашит в `server.mjs`; при занятом порту процесс завершится с
  понятным сообщением.
